- This chart has no reverse proxy in front of it; each service is reached by
  port-forwarding it directly. Run these commands, then open the URLs below:

     kubectl --namespace {{ .Release.Namespace }} port-forward svc/frontend 8080:8080
     kubectl --namespace {{ .Release.Namespace }} port-forward svc/image-provider 8081:8081
     kubectl --namespace {{ .Release.Namespace }} port-forward svc/flagd 4000:4000
     kubectl --namespace {{ .Release.Namespace }} port-forward svc/load-generator 8089:8089

  Webstore             http://localhost:8080/
  Image Provider       http://localhost:8081/
  Feature Flags UI     http://localhost:4000/
  Load Generator UI    http://localhost:8089/

  The webstore is fully self-contained on its own origin: the browser's
  same-origin paths (/images product images, /flagservice feature flags,
  /otlp-http trace export) are served by the frontend itself, which proxies
  them to image-provider, flagd, and the collector - so the single frontend
  port-forward above gives a fully working store. A Gateway may route those
  same paths straight to the backends to skip the frontend hop (see
  examples/public-hosted-httproute and otelCollectorHTTPRoute in values.yaml).

  This chart deploys the demo application and its own instrumentation agent
  only. Point the collector's otlp/observability-backend exporter at your
  platform's existing observability backend (see values.yaml, and
  examples/bring-your-own-observability for a worked example).
